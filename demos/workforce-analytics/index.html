Workforce hours, cut at the right midnight

A contact center needs the exact hours each agent worked on each day, in whichever timezone the viewer picks. Evening shifts cross midnight, five sites sit in five zones, and the raw export has duplicates and broken rows. This dashboard runs on the output of a BigQuery-style pipeline, rebuilt locally with DuckDB.

I first built this in BigQuery and Looker Studio on a company's real data. That data is confidential, so this public version runs the same SQL on synthetic data: invented people, sites and timestamps with the same shape and the same data problems.

How it works

  1. rawCSV loaded as text. A bad value can never break the load.
  2. stgTyped, deduplicated twice (by ID and by content), every unusable row flagged with a reason.
  3. coreStar schema with valid rows only, partitioned by day and clustered by agent and status.
  4. reportOne query with CTE phases splits each entry at local midnight with GENERATE_DATE_ARRAY + UNNEST. DST days come out as 23 or 25 hours.
  5. checksSplit hours equal unsplit hours in every timezone, and one agent-day is recomputed in plain Python.
